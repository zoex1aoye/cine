# Opening Protocol — 开场协议

## 模式分流（第一步）

| 信号 | 模式 |
|------|------|
| 「开场」「开工前梳理」；用户在场 | **交互** |
| 「写任务书」「让 agent 跑」 | **委托** |
| 无法判断 | 问：自己跟到底，还是交给 agent 独立跑？ |

同时判定**档位**（小修/中型/大型 × 影响）与**栈位**（player/api/ui/全栈/非代码），写入简报。影响档客观升档，不许自降。有 `specs/` 交接物或已有代码 → 迭代任务，问基线与变更类型。

## 交互模式（四步不可乱序）

### 站0 苏格拉底问诊

- 一次一问，上限 6 问；只问可能改变结论的
- 区分：事实 / 解释 / 价值 / 目标
- 结束输出六项：最初问题 / 真正问题 / 已确认事实 / 未验证假设 / 关键变量 / 下一准确问题
- **等用户确认后进①**

### ① 己见先行（红线）

列出 3–5 个决策点，请用户先表态。**用户表态前 AI 禁止推荐。** 用户说「直接听你的」→ 标注跳过并记入简报。

### ② 对等仲裁

冲突点：钢人用户直觉 + 钢人 AI 推荐 → 定位真分歧 → 双层解释 → 决策权归用户。可调用 `steelman`。

### ③ 糙版探路

最便宜形式：大纲 / 线框描述 / 样例交互。标「糙版」；问「哪里不是你想要的？」

### 输出：任务简报

确认的问题 / 档位·栈位 / 裁决记录 / 糙版反馈 / 执行规格 / 验收标准。

下游：**步骤 2 `to-prd`**。小修档简报 3 行可作 PRD 头部，仍须落 PRD 编号（用户明示跳过除外）。

## 委托模式

调研（先读 AGENTS + specs）→ 一轮 ≤5 问（选项+推荐）→ 任务书 ≤8000 字：

1. 开头五件事（目标/非目标/验收/时限/权限）
2. 我替领导拍的板（标「猜的」+猜错代价）
3. 界限（白名单路径）
4. 现状与任务 0
5. 任务 N（可断点：PROGRESS）
6. 规矩 + 完成条件

防五种死法：作弊达标 / 幻觉事实 / 失忆 / 一条道走到黑 / 静默事故。

## 边界

- 不管执行；过程纪律见 `execution-discipline`
- 方案未想清 → `grill-me`；单点取舍 → `steelman`
