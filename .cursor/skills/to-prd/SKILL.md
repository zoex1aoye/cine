# To PRD

## 上下游

- 上游：`opening-protocol` 任务简报（缺口大时先建议补开场）
- 下游：`to-tickets`（拒收无 PRD 编号）

## 第 0 步：档位与门槛

- 小修（≤3 能力点）→ 轻模板；中型/大型 → 完整轻 PRD
- 规范/基建/配置类：始终用轻模板，决策记录为核心
- 三类缺口必须问：MVP 边界、异常/空态、跨平台是否都要验。一次 ≤5 问

## 轻模板（默认）

落 `specs/prd/PRD-<YYYYMMDD>-<序号>-<slug>.md`，结构见 `specs/prd/TEMPLATE.md`：

- 编号 / 档位 / 栈位
- 要解决什么问题
- 用户故事 + 验收勾选
- ATDD 表
- 决策记录
- 实现约束（只引用 `.cursor/rules/…`，禁抄正文）
- 不做的事

## 完整轻 PRD（中型/大型）

在轻模板上追加：

1. 范围含/不含对照表
2. 关键交互或数据流（播放器/API 用序列或要点列表即可）
3. 风险与回滚
4. 大型可另写 `specs/design/`（见 TEMPLATE）

## 写后自检

- [ ] 每条验收可勾选、可演示
- [ ] 实现约束有指针无正文粘贴
- [ ] 不做的事非空（防范围蔓延）
- [ ] 编号唯一
