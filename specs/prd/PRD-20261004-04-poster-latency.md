## 要解决什么问题

Linux 上首页海报要等 9 个板块列表和手推接口都返回才开始下载。图片主域 `static.ztcuc.com` 已无法解析，DoH 对失败没有缓存，换域又按单张海报重试坏域名。

## 用户故事与验收标准

作为看首页的人，第一个板块的数据一到就看到海报，不用等后面的板块；坏掉的图片域名只失败一次。

- [x] 标签列表返回后立即画出板块，每个板块的视频列表独立灌入
- [x] `hand_data` 晚到再合并，不挡住板块请求
- [x] 图片域探测主域与备用域并行；备用先成功时最多再等 400ms
- [x] 测速只看状态码和 Content-Type，不下载整张测速图
- [x] DNS 失败、超时、403、非图片把该域记为会话内不可用；404 不拉黑
- [x] 新封面跳过已拉黑的域
- [x] DoH 对全部端点的确定性失败做 60 秒负缓存；成功解析仍优先于系统 DNS
- [x] `flutter test` 覆盖竞速、负缓存、失败判定和分批合并

## 不含

- 改服务端 `imgDomain` 配置
- 封面原图缩放参数
- 关闭 DoH
