# TV / 低端 Android 硬件解码健壮性与自愈体系
- 编号：PRD-20261003-03 ｜ 确认人：用户 ｜ 档位：中型×碰播放器·跨平台 ｜ 栈位：全栈 / player

## 要解决什么问题（1 段）

在低端 Android TV / 投影仪及联发科等 SoC 设备上，MediaCodec 驱动常出现解码失败，或静默假死（流已下载但无画面）。构建解码自愈体系：识别硬解失败日志特征、以「首帧是否已出」为依据的假死看门狗、受限机型软解降载，并在 Android 播放控制栏提供遥控器可直达的硬解/软解切换并记住偏好。

## 用户故事与验收标准

作为 TV 观众，我希望在播放各种编码视频时，即使电视硬解码器异常或驱动假死，播放器也能在数秒内自动感知并切换到可用解码模式；同时我可以使用遥控器主动切换硬解/软解。

- [x] 硬解失败日志特征（`looksLikeHwdecFailure`）覆盖 OMX/C2、dequeue output buffer、surface abandoned/invalid/lost、amediaerror 等；刻意不匹配泛化的 `mediacodec` + `error`，避免 HLS 单包告警误触发
- [x] 硬解假死看门狗：仅在「硬解生效 + 有视频轨 + 正在播放 + 未在缓冲」期间累计 5 秒，到点用 `estimated-vf-fps` 实测解码器是否出帧；确认无帧才回退软解；探测不可用时不回退
- [x] 回退/手动切换保留播放进度（mpv `start`）与暂停态；回退额度按播放器实例、按源计算；因硬解失败自动退到软解的，换集时重新尝试硬解
- [x] 软解降载：低内存档且软解时 `vd-lavc-skiploopfilter=nonkey`（含「设备本就无硬解」的初始路径），切回硬解恢复 `default`
- [x] 解码模式切换仅在 Android 显示；用户选择持久化（Hive `config`），下次启动沿用；遥控器可经 `↑` 进入控件栏并聚焦该按钮
- [x] `flutter analyze` 无 error；单元测试与 Widget 测试通过

| 非 Android | 桌面 / Web | 打开播放页 | 不显示解码徽标 |

## 决策记录
| # | 议题 | 结论 | 理由 | 日期 |
|---|---|---|---|---|
| 1 | 假死判据 | 用 `estimated-vf-fps` 实测出帧，而非 `position == 0` | 续播会让 position 立刻非零；音频照常推进 position 会掩盖视频假死 | 2026-10-03 |
| 2 | 探测不可用 | 视为正常 | 宁可漏判也不把网络问题误判成解码器问题 | 2026-10-03 |
| 3 | release 日志级别 | `warn`（仅 Android debug 用 `info`） | info 级日志逐行过 Dart 侧字符串匹配，1GB 设备上是纯开销 | 2026-10-03 |
| 4 | TV 按键 | 焦点在根节点才处理方向/确认键；控件栏可见时 `↑` 进入控件栏 | 祖先吞掉方向键会让底栏/顶栏按钮永远够不到 | 2026-10-03 |
| 5 | 自动回退不持久化 | 仅用户手动选择持久化 | 一次源的硬解失败不应让该设备永久软解 | 2026-10-03 |

## 风险与回滚
- `estimated-vf-fps` 在目标 SoC 上的表现须实机冒烟确认；若某设备该属性始终为空，会被误判为假死（回退一次软解，可被用户切回）
- 回滚：关闭 `HwdecWatchdog.setEnabled` 即可停用看门狗，日志特征回退与手动切换不受影响
