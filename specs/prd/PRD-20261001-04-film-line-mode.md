## 要解决什么问题

播放页「切换线路」对电影（各 CDN/清晰度线使用互不相同的 `source_name`，如 `BD国粤日三语中字` / `正片` / `1080P`）仍按「当前集名」过滤代表源与测速索引，导致：

1. 线路面板只显示当前一条（其余被当成「无当前集」隐藏）
2. 未落在测速 scope 内的线路 `playlistMs` 长期为 `null`，UI 永久「检测中…」

线上抽样（`id=572806` 蜡笔小新）：API `source_list_source` 25 组、解析后 22 条独立线路；VIP 列表与 SLS 无独有 URL，**不是解析漏线**。

## 用户故事与验收标准

作为观影用户，在电影详情/播放页打开「切换线路」时，我想看到该片全部可用线路及其测速结果，并能一键切到任意线路，以便在卡顿或画质不满意时换线，而不是卡在「检测中」且只剩一条。

- [ ] 电影类标题（各线路 `source_name` 不一致）线路面板展示全部 `usable` 线路（含当前选中）
- [ ] 进入播放页后各线路完成探测或失败终态，**不再**长期停留「检测中…」/「...」
- [ ] 切线优先对齐当前集名；无同名则回退该线路任一源（保持现有 `_switchLine` 三级逻辑）
- [ ] 剧集：切线仍优先同集；测速代表 URL 优先当前集，缺省时用该线首源（不因缺集而整线跳过测速）
- [ ] 单源标题也会跑测速（去掉 `_sources.length > 1` 门槛）
- [ ] `flutter analyze` 无 error；单测覆盖代表源回退与「全线路可列出」
- [ ] macOS 冒烟：蜡笔小新打开切换线路可见多条，且无永久检测中

## 关键行为

1. **代表源**：`lineName` → 优先 `matchesEpisode(当前集)`；否则该 `lineName` 下第一个源。
2. **测速**：对每个 distinct `lineName` 测一次代表 URL；禁止因「无当前集」整线跳过。
3. **线路列表**：按代表源读 `usable` / `playlistMs`；`!usable && !active` 仍隐藏失败线。
4. **切线**：沿用现有优先同集 → 同 sourceName → 该线任意源。
5. **单源**：`_sources.isNotEmpty` 即进入测速流程。

## 风险与回滚

| 风险 | 缓解 |
|---|---|
| 剧集线路更多、测速更久 | 仍按线路 distinct 测一次；缓存 TTL 12h |
| 切到无当前集的线落到第1集 | 已有 fallback；面板可显示代表源的 ep 名（可选，本迭代不做） |
| 回滚 | 恢复「无集匹配则跳过/隐藏」旧代表源逻辑 |
