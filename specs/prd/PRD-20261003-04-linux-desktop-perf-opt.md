# Linux / 桌面端播放性能与内存综合优化
- 编号：PRD-20261003-04 ｜ 确认人：用户 ｜ 档位：中型×碰播放器·跨平台 ｜ 栈位：全栈 / player

## 要解决什么问题（1 段）

在 Linux / 桌面环境下，应用播放 1080P 高清切片流时，常驻内存占用逼近 1GB（RSS ~930MB），且在无硬件 VAAPI 加速或纯软解/软件帧拷贝渲染回退路径下 CPU 占用达 1.5~1.8 核。需要针对桌面端/Linux 进行内核缓冲区收缩、软解参数加速、视频播放态高斯模糊合成剔除以及进播放页跨端图片缓存清理，在保证秒开与拖动无感的前提下降低约 150MB~200MB 内存并显著降低渲染与软解 CPU 开销。

## 用户故事与验收标准

作为 Linux / 桌面客户端用户，我希望在享受原画质、平滑拖动与即时播放体验的同时，客户端能占用更少的内存（减少 150MB+）和更低的 CPU 算力，避免机器发热与风扇狂转。

- [x] 桌面端播放器缓冲区收缩：桌面端 demuxer 缓冲区从 128MB+64MB 优化收敛为 48MB+24MB（预读 25s / 缓存 40s），既保留充足的前后 Seek 冗余，又释放超 100MB 内存
- [x] 软解 CPU 加速：启用 `vd-lavc-fast: yes`，在软解模式（非 Android/非硬解）下启用非关键去块跳过或多线程快速解码优化，降低软解 CPU 运算
- [x] 播放态移除视频槽高斯模糊底层：在 `_startPlayRequested` 起播后，视频容器底层的 `_buildBlurredPosterBase` 替换为纯色黑底，彻底消除不必要的离屏渲染通道（Offscreen Buffer）与逐帧模糊计算
- [x] 进播放页全局修剪图片缓存：进播放页主动修剪未引用图片缓存，释放首页旧海报
- [x] `flutter analyze` 零 error，`flutter test` 通过，桌面端播放/Seek 冒烟验证通过

## 决策记录
| # | 议题 | 结论 | 理由 | 日期 |
|---|---|---|---|---|
| 1 | 桌面端缓冲尺寸 | 前向 48MB / 后向 24MB | 1080P 码率 ~4Mbps 下足以支撑 90 秒前向与 45 秒后向缓存，128MB 过于富余 | 2026-10-03 |
