# 测速前 N 条后早开播
- 编号：PRD-20261002-01 ｜ 确认人：用户 ｜ 档位：中型×碰播放器 ｜ 栈位：player

## 要解决什么问题（1 段）

线路很多时冷启动要等全部测速结束才 init，等待过长。改为只计本轮新测的前 3 条并行测完后用 `SourcePicker` 选优早开播；缓存命中与 Champion 快启保留；开播后继续测、未点播放前可升级；点播放中止测速。

## 用户故事与验收标准
作为观众，我想要线路较多时尽快进入可播状态，以便少盯测速进度。
- [x] 本轮待测 ≥3 时：并行测完前 3 条后即可 `SourcePicker` 选优并 init（若尚未 init）（代码侧；冒烟待确认）
- [x] 缓存命中不算进「前 3」；Champion 复测快启保留
- [x] 前 3 条结束后仍无可用：继续测后续，一有可用立刻 init
- [x] 早开播后其余线路继续测；未点播放前更好线自动 upgrade
- [x] 用户点播放后中止剩余测速（现有行为）

## ATDD
| 场景 | 给定条件 | 操作 | 预期结果 |
|------|----------|------|----------|
| 早开播 | 10 条待测、无缓存 | 进页 | 前 3 测完即可进 init/ready，不必等 10 |
| 缓存不算 | 2 条缓存命中 + 5 条待测 | 进页 | 先并行测 3 条待测再早开播（或 Champion 先启） |
| 首批全挂 | 前 3 不可用，第 4 可用 | 进页 | 测到第 4 可用后立刻 init |
| 升级 | 早开播后后台测出更好线且未点播放 | 等待 | 自动切到更好线 |
| 中止 | 早开播后点播放 | 点击播放 | 剩余测速 abort |
